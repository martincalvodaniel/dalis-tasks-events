# Planning Rules

- Write product explanations in Spanish; keep code identifiers, paths, technical literals, and commit messages in English.
- `master.md` is the entry point; `iterations.md` defines delivery order; `workflow.md` defines budget and commit rules; `iteration-log.md` records evidence.
- Keep product requirements, accepted planning decisions, implementation status, and unresolved deployment prerequisites distinct.
- Update dependent documents when a decision changes. Never mark an iteration complete until its acceptance criteria and applicable validation have passed.
- Link to actual repository paths or primary documentation. Do not record credentials, actual invited email addresses, or other personal data.
- Do not turn estimated usage percentages into guaranteed costs or silently expand the MVP.
- Preserve the root iteration closing protocol, including a commit on the current branch and a question about both usage windows.
